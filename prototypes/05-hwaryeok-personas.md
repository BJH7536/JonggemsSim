## 2. 페르소나를 움직이는 시스템 (검증된 뼈대)

시뮬레이터로 가져갈 때 **그대로 유지할 것**들. 전부 Chrome 실구동으로 검증됐다.

1. **톤 6종 체계**: hype / worry / info / mock / cheer / question. 페르소나 = 톤의 부분집합.
   템플릿은 이벤트별로 만들고 톤 태그를 달아, 페르소나가 자기 톤만 골라 말한다.
   → 템플릿 수는 이벤트×톤으로만 늘고, 페르소나 추가는 공짜에 가깝다.
2. **fact/flavor 분리**: 버스트의 첫 줄만 사실 슬롯(수치·사고명)을 말하고 나머지는 순수
   리액션. 실제 채팅의 "한 명이 숫자를 읊으면 나머지가 소리 지른다" 구조이자,
   자연스러운 문장과 슬롯 검증을 양립시키는 장치.
3. **검증 게이트**: 사실 슬롯 포함 검사 + 직전 3회 유사도 <0.72 + 재실패 시 발화 폐기.
   LLM으로 바꿔도 이 게이트는 밖에 남는다 (환각·반복 방어).
4. **타이밍**: 첫 반응 120~300ms, 이후 줄 90~310ms 스태거. 잡담 주기는 시청자 규모에
   로그 비례(3.6s→1.1s), 30k 이상 대형 방송은 버스트 +1줄. 이벤트 무게별 버스트
   1~4줄 (대참사 4 > 고배율 수습·기름화재 3 > 사고·언락 2 > 실패·잡담 1).
5. **손실 무연출·획득 과연출의 채팅판**: 대참사엔 4연타 폭발, 수습 실패엔 마른 1줄.
   채팅도 규약 2를 따른다.
6. **C3 — 연출 전용**: 채팅은 게임 상태를 읽고 말만 한다. 룰 수치(시청자·보상·사고)에
   일절 관여하지 않는다. 밸런스와 채팅을 독립적으로 튜닝할 수 있는 이유.
7. **안전장치**: showId 토큰 + phase 검사로 방송이 바뀌면 지연 발화 폐기. 피드 70줄 상한.
8. **`[LLM-INTEGRATION-POINT]`**: 교체 지점은 `Chat.compose()` 하나. 입력 = 페르소나
   프로필(1장) + 사실 슬롯 + 게임 상황, 출력 = 발화 1줄 (게이트는 밖에서 검사).

## 3. 현재 구조의 한계 — 시뮬레이터가 넘어야 할 것

- **페르소나 = 톤 필터일 뿐.** 같은 톤이면 누가 말해도 같은 문장이다. 개성이 어휘·문체가
  아니라 선택 확률로만 존재한다. (LLM 프로필이 1차 해법, 페르소나 전용 템플릿이 0차 해법)
- **기억이 없다.** 방송 안에서 일어난 일을 아무도 기억하지 못한다. 대참사 3번을 겪어도
  뉴비는 여전히 처음 온 사람처럼 말한다.
- **서로 대화하지 않는다.** 8명이 전부 스트리머(게임 이벤트)만 본다. 뉴비의 질문에
  고인물이 답하는 일이 구조적으로 불가능하다.
- **등장·퇴장이 없다.** 시청자 수는 300→수십만으로 변해도 채팅 인격은 고정 8명.
  숫자(규모)와 인격(캐스트)이 분리되어 있다.
- **스트리머와의 관계가 변하지 않는다.** 잘하든 못하든 응원봉은 영원히 팬이고
  냉정한미식가는 영원히 시큰둥하다.

## 4. 스트리머 시뮬레이터 확장 설계

### 4.1 페르소나 정의 모델 (제안)

현재 3요소(닉·색·톤)를 다음 7축으로 확장한다. 1장의 시트가 이 모델의 견본이다.

```
페르소나 = {
  정체성: 닉네임 · 색 · (선택) 뱃지,
  동기: 왜 이 방송을 보는가 — 발화의 뿌리,
  톤 레퍼토리: 기존 6톤의 부분집합 (유지),
  장르 선호: 게임 장르별 흥미 가중치 — 종합게임 방송의 핵심 축,
  관계 변수: 호감(스트리머에 대한) · 신뢰(스트리머 실력에 대한) — 방송 간 누적,
  라이프사이클: 뜨내기 → 정착 → 고정닉 → 구독자 (또는 이탈),
  발화 역할: fact 담당 여부 · 소음 담당 여부,
}
```

- **장르 선호**가 "종합게임"을 게임답게 만든다: 호러를 켜면 불멍장인이 살아나고
  안전제일이 비명을 지르고 냉정한미식가는 "또 호러냐"라고 한다. 같은 캐스트가
  게임 선택에 따라 다른 채팅을 만든다 — 게임 선택 = 채팅 편성표.
- **관계 변수**는 신선도 감쇠와 같은 이유로 필수다: 변하지 않는 반응은 반복되는 순간
  죽는다. 냉정한미식가가 처음으로 "인정"이라고 말하는 순간을 만들 수 있어야 한다.

### 4.2 신규 페르소나 후보 (기존 3축 덮개를 확장)

| 후보 | 자리 | 왜 흥미로운가 |
|---|---|---|
| 안티 | 응원봉의 대립쌍 | 팬덤 vs 안티 티키타카. 잘해도 꼬투리 — 스트리머 멘탈 관리라는 새 축 |
| 큰손 | 도네 이벤트의 인격화 | 익명 도네를 캐릭터로. 변덕스러운 큰 도네가 방송 목표를 흔든다 |
| 매니저(모더) | 채팅의 질서 축 | 안티를 견제하고 뉴비를 안내 — 채팅 내부에 드라마 생성 |
| 잠수함 | 침묵의 인격화 | 평소 눈팅만 하다 결정적 순간에만 한 줄 — 그 한 줄의 무게 |
| 유목민 | 길가던행인의 상위호환 | 타 방송과 비교하며 넘나든다 — 경쟁 방송의 존재를 채팅으로 암시 |
| 밈 제조기 | ㅋㅋ자판기의 상위호환 | 방송 사건을 별명·유행어로 만들어 되풀이 — 방송 내 기억의 의인화 |

### 4.3 티키타카 (페르소나 간 대화)

이벤트 → 발화 1홉 구조를 이벤트 → 발화 → **반응 발화** 2홉으로 확장한다.
1장의 대립쌍(불멍장인↔안전제일, 응원봉↔안티, 뉴비→고인물)이 반응 규칙의 기본표.
버스트 스태거(90~310ms)가 이미 있으므로, 두 번째 홉은 "직전 발화를 사실 슬롯으로 받는
버스트"로 구현 가능 — 기존 게이트 구조를 그대로 쓴다.

### 4.4 규모와 캐스트의 연결 (등장·퇴장)

- 시청자 수 구간별로 활성 캐스트가 늘어난다: 소규모(고정닉 위주) → 중규모(뉴비·뜨내기
  유입) → 대규모(안티·큰손·유목민 등장). 언락 임계처럼 **캐스트 자체가 성장 보상**이 된다.
- 이탈도 인격화: 길가던행인이 "슬슬 가볼게요"라고 말한 뒤 시청자 수가 빠지면,
  손실 무연출 원칙을 지키면서도 손실에 서사가 생긴다.

### 4.5 우선순위 제안

1. 페르소나 전용 어휘·문체 (3장 첫 한계 — 톤 필터 탈피): 템플릿에 페르소나 태그 추가부터
2. 관계 변수 + 방송 간 누적 (localStorage): "냉정한미식가의 첫 인정" 같은 순간 설계
3. 티키타카 2홉: 대립쌍 2개(불멍↔안전, 뉴비→고인물)만 우선
4. 장르 선호: 시뮬레이터의 게임 선택 시스템과 함께
5. 신규 캐스트·등장퇴장: 규모 시스템이 잡힌 뒤
