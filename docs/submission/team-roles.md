## 분업 방식 — "숫자를 만드는 사람과 말을 만드는 사람"

이 게임의 핵심 설계 원칙은 **C3 — "AI 시청자는 관측하고 말만 한다. 게임의 숫자는 결정론
규칙이 소유한다"**이다. 팀 분업을 이 경계선에 정확히 맞췄다. 제품 구조와 팀 구조를 일치시켜
서로의 작업이 충돌하지 않게 한 것이 이 팀의 협업 방식이다.

- 근거 문서: `docs/decisions/ADR-001-team-split.md`, `CONTRIBUTING.md`
- 소유 경계: `data/`(기획) · `engine/`·`tools/`(관객) · `games/`(무대)
- 공동 소유는 **`docs/contract.md`(이벤트 스키마·데이터 형식 계약)** 하나뿐이며, 이 문서를
  바꾸는 PR만 상호 리뷰를 필수로 했다
- 3인 전원이 각자 AI 에이전트(Claude Code)와 협업했고, 모든 산출물은 브랜치 + PR을 거쳤다

## 각자 실제로 맡아 구현한 영역

### 소윤 — 기획 (AI 시청자 콘텐츠)

- AI 시청자 **페르소나 8종 설계** — 불멍장인·안전제일·10년차주방장·오늘첫방문·ㅋㅋ자판기·
  냉정한미식가·응원봉·길가던행인. 각자의 동기·말투·톤 레퍼토리를 정의
  (`prototypes/05-hwaryeok-personas.md`)
- 캐스트가 임의 나열이 아니라 **3축(위험 선호 / 정보 깊이 / 애정 온도)을 덮도록** 설계
- **"공명 모델" 원안 공동 발안** — "각 페르소나가 흥미도 벡터를 갖고, 이벤트가 전체에
  전달되며, 임계 이상 반응한 페르소나가 시청자를 늘린다". 특히 **변이(mutation)** 개념
  ("한 원형에서 나온 시청자가 전부 같으면 단조롭다")은 이후 검증에서 *생태계 단일문화
  고착을 막는 장치*로 확인되어 그대로 구현됐다

### 정훈 — 개발 / 관객 (AI 시청자 시스템)

- **AI 시청자 채팅 엔진** — 톤 6종 체계, 사실 슬롯/리액션 분리, 페르소나별 캐스팅
  (`games/shell/chat.js`)
- **검증 게이트** — 룰이 넘긴 수치가 발화에 실제로 포함됐는지 검사, 직전 발화와의 유사도
  상한, 실패 시 발화 폐기. **LLM으로 교체해도 게이트는 바깥에 유지**되는 구조
- **LLM 통합 설계** — 프록시 경유 실제 LLM 발화, 전 구간 폴백(타임아웃·오류·미배포 시
  로컬 템플릿), 비용 상한 (`proxy/README.md` 설계 원칙 4가지)
- **공명 판정층 구현** — 자극 벡터 × 원형 흥미도의 내적으로 유입을 배분, 호오(valence)로
  유입의 질을 나누고, 변이로 이웃 원형에 확산, 채널 이월과 다양성 보상
  (`docs/decisions/ADR-004-resonance-layer.md`)
- **기획 지원 도구** — 페르소나 부스(게임 없이 반응 확인), 공명 샌드박스(판정층의 실행
  가능한 사양). 둘 다 실제 엔진·실제 데이터를 그대로 호출해 도구가 사양과 어긋날 수 없게 했다
- 상호 코드 리뷰 — 사실 줄이 게이트에서 조용히 폐기되던 결함, 방송 종료 타이머가 다음
  방송을 끝내던 버그 등을 발견·수정하고 재발 방지 검사를 자체 점검에 추가

### 현재 — 개발 / 무대 (게임과 배포)

- **방송 셸** — 게임 선택 허브, 방송 루프, 시청자 경제(획득·이탈·언락), 게임 단위 신선도,
  방송 리포트(시청자 추이 그래프), 스트리머 캠·플랫폼 크롬 등 "방송 플랫폼 안에 있다"는 연출
- **게임↔셸 계약 설계·구현** — 게임이 셸에 등록하고 무대 표면(`stage`)만으로 동작하는 구조.
  새 게임 추가 시 셸과 다른 게임을 건드리지 않는다 (`docs/contract.md` 4절)
- **게임 5종 구현** — 화력쇼(수습 윈도우), Giving Up On It(등반 물리·조작감 3차 개선),
  주머니 괴수(턴제 상성·연승), 해체쇼(판독 대 감컷 배당), 풍선쇼(**WebGL 3D**·익음배수·콤보).
  다섯 게임이 **각각 다른 리듬으로 같은 명제**("안전한 플레이가 최악")를 구현한다
- **3D 렌더러** — 풍선쇼는 WebGL로 그린다. 오프스크린에 렌더한 뒤 셸의 2D 캔버스로 합성해,
  깊이 버퍼·셰이더 조명을 쓰면서도 클립 자동 캡처와 게임↔셸 계약을 그대로 지켰다
- **윈도우 데스크탑 셸** — 페이지 자체가 스트리머의 PC다. 아이콘 더블클릭 → JGS.tv 창 개시 →
  카운트다운·스팅어 → 라이브 → 데스크탑 복귀. 작업표시줄 송출 프로그램 `● REC` 연동
- **AI 생성 아트 파이프라인** — AetherAI로 몬스터·어종·배경·VFX·런처 아이콘을 생성하고,
  마젠타 키잉·알파 트림·96px 최적화·재실행 가드까지 자동화 (`tools/optimize-images.ps1`,
  `tools/trim-alpha.ps1`). 생성물이 지시를 무시한 경우 코너 샘플 키잉으로 구제
- **방송 몰입 연출** — 도네이션 배너, 심박 카운터, 온보딩, 페이스 압박, 치지직풍 UI 리스타일
- **밸런스 검증** — 화력쇼 보상·언락 임계를 몬테카를로 시뮬 4차 라운드로 확정
- **배포** — GitHub Pages 파이프라인, 로드 예산 가드, LLM 프록시(Vercel) 구축·운영
- **장애 내성** — 게임이 예외를 던져도 방송 루프가 죽지 않고 '게임 튕김'으로 정산된다
- **자체 점검 하네스** — 신선도 회전·채팅 게이트·게임 계약·지형 기하·배포 payload 예산

## 협업에서 실제로 작동한 장치

1. **계약 문서 우선** — 코드보다 `contract.md`가 규범이다("어긋나면 문서가 맞다"). 각자
   AI 에이전트를 쓰는 팀에서 가장 큰 위험은 "세 세션이 서로 다른 진실을 만드는 것"인데,
   계약 문서가 그 방파제 역할을 했다
2. **결정은 ADR로 남긴다** — 팀 분업(ADR-001), 공명 판정층 도입(ADR-004). 무엇을·왜·
   기각한 대안까지 적어 다른 세션이 같은 결정을 재발명하지 않게 했다
3. **소유권과 검증권의 분리** — 예: 이벤트 발행 코드는 무대가 구현하되 계약 위반 지적
   권한은 관객에게 있다. 판정층 데이터는 기획이 저작하되 상수 범위는 무대가 검증한다
4. **작업 결과는 기계 검사로 고정** — 자체 점검 77건이 조용히 깨지면 게임이 뒤집히는
   로직(신선도 회전, 채팅 검증 게이트, 배분 총량 보존, 게임 명제 순서)을 지킨다
