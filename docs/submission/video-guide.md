## 0. 찍기 전 준비 (3분)

1. **브라우저 창을 가로로 크게** — 최소 1600×900. 채팅창이 오른쪽에 보여야 한다(이 게임의 핵심)
2. **https://bjh7536.github.io/JonggemsSim/** 접속 (또는 로컬 `python -m http.server 8770`).
   위 촬영 가능 조건 3개를 먼저 확인한다
3. **채널을 어느 상태로 보여줄지 정한다** — 콘솔에서
   `localStorage.removeItem('jonggems-channel-v1')` 후 새로고침하면 초기화된다.
   **추천: 2~3판 미리 해두고 찍기** (구독자·채널 색깔이 채워져 있어야 시뮬레이터로 보인다)
4. **탭을 활성 상태로 유지** — 백그라운드로 가면 rAF가 멈춰 방송이 정지한다
5. 소리: 합성음 SFX가 있다. 켜고 찍으면 좋지만 필수는 아니다
6. 녹화 도구: Windows `Win+G`(Xbox Game Bar) 또는 OBS. **커서가 보이게** 설정

## 2. 꼭 화면에 담겨야 하는 것 (우선순위)

1. **오른쪽 채팅창이 계속 보일 것** — 이게 안 보이면 그냥 미니게임 모음으로 보인다
2. **사고 → 수습 → 채팅 폭발**의 인과가 한 화면에 — 이 게임의 명제다
3. **대참사 순간의 시청자 폭등** — "실수가 콘텐츠"라는 역설
4. 리포트의 **원형별 순증감**과 **채널 색깔** — AI 관객이 시스템이라는 증거
5. 게임을 바꿨을 때 **채팅 성격이 달라지는 것**

## 3. 하면 안 되는 것

- AI로 화면을 만들거나 합성하지 않는다 (요건 위반)
- 남의 영상·이미지를 넣지 않는다
- 자막·나레이션은 넣어도 되지만 **플레이 화면이 중심**이어야 한다

> 참고: **게임 안의 아트를 AI(AetherAI)로 생성한 것은 요건 위반이 아니다.** 이 조항은
> *영상*의 조작·합성을 금지한다. 에셋 생성 내역은 제출물 ④에 출처로 밝힌다 (요건 §4).

## 5. 문제가 생기면

| 증상 | 원인·대처 |
|---|---|
| 아이콘이 3개뿐이다 | **캐시다.** `Ctrl+Shift+R`로 하드 리프레시하면 5개가 된다 (맨 위 참조) |
| 화면이 깨져 보인다 | 같은 원인. 하드 리프레시하면 정상이다 |
| 방송이 멈춘다 | 탭이 백그라운드로 갔다. 탭을 활성 상태로 두고 다시 시작 |
| 채팅이 안 뜬다 | 이벤트가 없는 조용한 구간이다. 요리를 올리거나 사고를 기다린다 |
| 채팅 배지가 "로컬 시뮬레이션" | 프록시 미설정 상태. **정상이다** — 규칙 기반 채팅도 완전 동작한다. LLM 라이브로 찍고 싶으면 Vercel 키 설정 후 |
| 사고가 안 난다 | 모드를 **속성**(25%)이나 **무모**(60%, 해금 필요)로. 정석은 5%라 잘 안 난다 |
| 게임이 튕긴다 | 셸이 잡아 '게임 튕김'으로 정산한다(PR #12). 방송은 살아 있으니 재방송하면 된다 |
