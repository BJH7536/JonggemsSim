# 반사속도 게임 설계 — 풍선쇼 (광클쇼는 철회)

> 2026-08-10. 발단: 사용자가 유튜브 쇼츠 "구마유시 반응속도 테스트"(@5GAZI)를 레퍼런스로 제시.
> 원본 영상은 재생 확인 실패(자동화 탭에서 `readyState 0`) — 아래 규칙은 사용자 구술로 확정했다.
> 소유: `games/` = 무대(현재). `data/events/` 초안은 소윤 협의 대상 (ADR-001).
>
> **최종 상태 (2026-08-10)**: 두 게임을 다 만들었으나 같은 날 사용자 결정으로 **광클쇼는
> 삭제**됐다 (심연낚시 삭제와 함께). 출시되는 것은 **풍선쇼 하나**다. §2·§5의 광클쇼 기록은
> 왜 그런 게임이 있었고 왜 없어졌는지를 남기려고 지우지 않는다.

## 1. 레퍼런스에서 확정된 규칙

사용자 구술로 확정된 원본 게임의 규칙:

- 버튼(표적)이 **연속으로 스폰**된다. 클릭을 기다리지 않는다
- **동시에 여러 개**가 화면에 있을 수 있다
- 안 누른 버튼은 **시간이 지나면 사라진다** (놓침 = 손실)
- **30초 제한**

BATAK 리액션 보드(한 번에 하나, 치면 다음이 뜸)와 결정적으로 다른 점은 **스폰이
플레이어 입력과 무관하다**는 것이다. BATAK은 아무리 느려도 화면이 밀리지 않는다(내 페이스).
이쪽은 밀려온다 — 처리율이 스폰율을 못 따라가면 화면이 잠식된다.

## 2. 왜 두 개인가

같은 뼈대(연속 스폰 + 만료 + 클릭)에 **리스크 층만 다르게** 얹은 두 게임이다.
설계 검토에서 세 가지 리스크 층을 놓고 골랐다:

| 안 | 리스크 층 | 판정 |
|---|---|---|
| A 익힘 | 버튼이 부풀수록 비싸지고, 자연 파열하면 손실 | **채택 → 풍선쇼** |
| B 폭탄 | 누르면 안 되는 표적을 섞는다 | 기각 — 반사 게임에 "누르지 마라"는 손을 늦추는 게 정답이 되는 구간을 만든다 |
| C 콤보 | 연속 처리로 배수를 쌓고, 하나 놓치면 0 | 채택 → 광클쇼 → **당일 철회·삭제** |

C는 검토 때 "종겜스 공통 명제(안전한 플레이가 최악)를 못 만든다"고 지적했다 —
빨리 누르는 게 유일한 정답이라 리스크 **선택**이 없다. 사용자가 그럼에도 C를 지정했고,
A도 함께 만들기로 했다. 따라서 **광클쇼는 실행 순도 100%의 게임**으로 의도된 것이며,
공통 명제는 풍선쇼가 담당한다. 라인업 다양성 측면에서 기존 5종(반사+판단/긴장/수읽기)에
없던 "순수 처리력" 축이 하나 생기는 것으로 본다.

## 3. 공통 뼈대

| 항목 | 값 |
|---|---|
| 방송 길이 | 180초 (기존 5종과 동일) = **30초 라운드 × 6** |
| 라운드별 스폰율 배수 | ×1 → 1.3 → 1.6 → 2.0 → 2.4 → 2.9 |
| 입력 | 마우스 클릭 — `pointer(p, 'down')` (contract 4.3, 좌표는 0..960 × 0..430) |
| 라운드 전환 | 스탬프 + `emit('round_up', {r})` |
| 연쇄 미터 | `usesChain: true` — 셸 미터를 배수 표시로 재사용 |
| 도네 | `stage.donRoll(dt, 9, .45)` — 셸 소유 (contract 4.2, 규약 5) |
| 아트 | 벡터부터. AetherAI는 나중에 얹는 층 (`imgReady` 폴백 규약) |
| 게임 내부 신선도 | 없음 — 반복 파밍 구조가 없다. 규약 4는 셸의 게임 단위 신선도가 담당 |

라운드는 **게임이 소유하는 내부 구획**이다. 셸의 방송 시계(180초)는 건드리지 않는다.

## 4. 풍선쇼 (`balloon`)

풍선이 떠올라 계속 부푼다. 클수록 터뜨렸을 때 비싸고, 너무 키우면 저절로 터진다.

### 규칙

- 스폰 base **0.9/s** (라운드 배수 적용 → R6 2.6/s)
- 수명 **2.6초 고정.** 라운드가 올라도 수명은 그대로고 스폰율만 오른다 —
  후반에는 동시에 부푸는 게 많아 "익힐 여유"가 사라지는 방식으로 압박이 온다
- 반지름 14 → 40px 선형, 익음도 `t = 경과/수명` (0..1)
- 클릭 획득 = `30 × (1 + 3t)` → **30 ~ 120** (익음배수 ×1.0 ~ ×4.0)
- 익음도 ≥ 0.9에서 터뜨리면 **만개** — 스탬프 + `emit('bloom')`
- 자연 파열(만료) = `lose(140)` **조용히** (규약 2). 자연 파열은 정의상 항상 t=1에서
  일어나므로 손실은 상수다 — 즉시 터뜨림(+30) 4~5회분이라 하나 놓치면 안전 플레이의
  벌이가 통째로 날아간다
- **콤보 없음.** 리스크는 "지금 터뜨릴까 더 키울까"와 "몇 개를 동시에 키울까"에서만 온다

### 공통 명제

안전한 플레이(보이는 족족 즉시 터뜨림)는 절대 안 놓치지만 전부 ×1.0이다.
지르는 플레이(4~5개를 동시에 익혀 만료 직전 쓸어담기)는 배점이 몇 배지만,
스폰율이 계속 오르는 중이라 만료가 겹치는 순간 무더기로 잃는다.
**처리량과 단가의 교환**이 매 순간 강제된다.

### summary()

처리 수 / 평균 익음도 / 자연 파열 수 / 최고 동시 부풀림

## 5. 광클쇼 (`click`) — 철회됨 (2026-08-10 삭제)

> 만들어서 검증까지 마쳤으나 같은 날 삭제 결정. 아래는 무엇이었는지의 기록이다.
> 되살릴 일이 생기면 커밋 `de57234`의 `games/click/game.js` · `data/events/click.js`에 원본이 있다.

과녁이 계속 뜬다. 크기도 배점도 고정. 연속 처리로만 배수가 오르고, 하나 놓치면 0.

### 규칙

- 표적 반지름 **24px 고정**
- 수명 **R1 1.9초 → R6 1.0초** (라운드마다 짧아진다 — 풍선쇼와 반대로 여기선 수명이 압박축)
- 스폰 base **1.2/s** → R6 3.5/s (인간 처리 한계 근처)
- 콤보: 처리 성공마다 +1. 배수 = `1 + floor(콤보/5) × 0.5`, **상한 ×5.0** (콤보 40)
- 클릭 획득 = `22 × 콤보배수` → **22 ~ 110**
- 놓침(만료) = `lose(80)` + 콤보 0 리셋, **조용히** (규약 2)
- 배수 마일스톤(×2·×3·×4·×5)에서 스탬프 + `emit('combo_up', {x})`

### summary()

총 처리 / 최고 콤보 / 놓침 / 도달 라운드

## 7. 밸런스

§4·§5의 수치는 **1차 조율 초안**이다. `tools/balance-sim.js`로 스윕해 확정한다.
확인해야 할 실패 모드 둘:

- **광클쇼 R5~R6가 "무조건 콤보 끊김"이 되면** 후반 배수 설계가 죽고 게임이 "언제 끊기나"만
  남는다. 스폰율 상한을 인간 처리 가능 범위(≈3/s) 근처로 유지해야 한다
- **풍선쇼 만개 보상이 너무 세면** "무조건 끝까지 키우기"가 지배 전략이 되어 A의 선택 구조가
  무너진다. 즉시 처리 전략 대비 우위가 있되 지배적이지 않아야 한다

### 1차 손계산 (2026-08-10, 스윕 전)

R1 기준 스폰 0.9/s로 두 전략을 비교하면:

| 전략 | 초당 수지 |
|---|---|
| 안전 (즉시 ×1.0, 놓침 0) | `30 × 0.9` = **+27/s** |
| 욕심 (만개 ×4.0, 놓침 20%) | `0.8×120×0.9 − 0.2×140×0.9` = **+61/s** |
| 욕심 (놓침 50%) | `0.5×120×0.9 − 0.5×140×0.9` = **−9/s** |

손익분기 놓침률 = `120 / (120+140)` ≈ **46%**. 욕심이 안전을 이기려면 놓침을 약 35% 아래로
유지해야 한다 — 지배 전략도 아니고 함정도 아닌 구간이라 의도한 모양이다.

⚠ 남은 우려: **시작 시청자 300에 파열 손실 140**이라 초반 버퍼가 얇다. 아무것도 안 누르면
2~3초에 방송이 끝난다(규약 1대로 시청자 = 체력이니 방치의 벌 자체는 맞다). 실플레이에서
초반이 너무 가혹하면 `START_VIEWERS`만 올린다 — 위 수지 곡선은 건드리지 않는 손잡이다.

### 스윕 결과 (2026-08-10, `node tools/balance-sim.js` · 전략당 400회 평균)

180초를 0.05초 스텝으로 돌리고, 플레이어는 목표 익음도 `T`를 넘긴 것 중 가장 익은 풍선을
누른다. 손 속도 상한 3.2회/s, **조준 오차 σ = 0.07**(≈180ms를 익음도로 환산).

| 전략 (목표 익음도) | 최종 시청자 | 전용 점수 | 터뜨림 | 자연 파열 |
|---|--:|--:|--:|--:|
| 보이는 족족 (0.05) | 12,209 | 78,127 | 301 | 0 |
| 살짝 익혀 (0.35) | 20,113 | 129,984 | 299 | 0 |
| 중간 (0.55) | 25,410 | 164,731 | 298 | 0 |
| 많이 익혀 (0.75) | 30,623 | 198,908 | 297 | 0 |
| **만개 노림 (0.90)** | **33,704** | **213,755** | 293 | 3 |
| 한계까지 (0.97) | 29,611 | 169,944 | 272 | 23 |

**판정**: ① 안전한 플레이가 최악이다 (족족 대비 최적 ×2.76) ② 최적점이 **만개 창(0.90)**에
정확히 놓인다 ③ 그 너머로 미루면 파열이 3 → 23으로 뛰며 **오히려 손해**다. §7이 우려한
"무조건 끝까지 키우기가 지배 전략"은 성립하지 않는다.

> **모델 주의**: 조준 오차를 빼고 돌리면 0.97 전략이 파열 0으로 지배 전략이 된다.
> 사람이 100% 정확히 누른다고 가정하면 이 게임의 위험이 통째로 사라진다는 뜻 —
> 오차 항이 이 시뮬레이션의 핵심이지 장식이 아니다. σ는 추정치이므로 실플레이로
> 보정해야 한다 (σ가 0.03이면 최적점이 0.95 쪽으로, 0.12면 0.85 쪽으로 밀린다).

## 8. 알려진 리스크

둘 다 클릭 게임이라 **서로의 신선도를 잡아먹을 수 있다.** 규약 4의 게임 단위 신선도는
셸이 게임 id별로 굴리므로 수치상으로는 분리되지만, 체감이 겹치면 플레이어는 "같은 게임 두 번"으로
느낀다. 전략이 정반대(풍선=버티기, 광클=즉시)라 갈릴 것으로 보지만 플레이 검증이 필요하다.
