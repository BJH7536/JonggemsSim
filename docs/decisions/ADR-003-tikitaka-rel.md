# ADR-003 — 티키타카 2홉·관계 변수는 발화층 연출 전용으로 최소 도입

- **무엇을**: ① 2홉 티키타카 — 발화가 화면에 나간 뒤 대립쌍 상대가 확률로 받아친다
  (`data/tikitaka.js` pairs, 엔진 `Chat.maybeReply`). ② 관계 변수 — 큰 사건(버스트 무게 ≥3)마다
  trust 1 누적(localStorage), 임계 돌파 시 1회성 발화(moments, `Chat.bumpTrust`).
- **왜**: 페르소나 시트 4.3·4.5의 예고분 (영역 B 산출물 ⑤). "서로 대화하지 않는다"와
  "기억이 없다"는 3장 한계의 최소 해소.
- **경계**: 전부 발화층이다. trust는 경제·룰 수치에 어떤 경로로도 들어가지 않는다 (C3).
  공명 모델(판정층, resonance-model.md)은 도입 게이트 미통과 상태라 건드리지 않았고,
  v2 예약 필드(interest/valence/threshold)도 쓰지 않는다 — 이 구현은 게이트와 무관하게 안전.
- **신호 선택**: trust 신호는 버스트 무게 하나다 — 게임 의미를 모르는 엔진이 쓸 수 있는
  유일한 흥미도 신호 (셸 클립 캡처와 같은 원리). 이벤트 의미 기반 신호는 공명 모델로.
- **대안**: 직전 발화 인용({quote} 슬롯) 응답 — 40자 리듬과 이중 이스케이프 경계가 복잡해
  범용 응답 템플릿으로 시작. 물리면 그때 추가.
- **한계 명시**: 응답은 원발화 내용과 무관한 범용 문장이다 (성격만 맞음). 대립쌍 3룰·모멘트
  3개가 시작점 — 저작 확장은 소윤 소유 (`data/tikitaka.js`, validate가 계약 검사).
