# ADR-001: 팀 분업 — 기획 / 관객 / 무대

- 일자: 2026-08-06
- 상태: 확정
- 참여: 소윤(기획), 정훈(엔지니어), 현재(엔지니어)

## 결정

| 담당 | 영역 | 소유 |
|---|---|---|
| **소윤** | 기획 | AI 시청자 페르소나·반응 콘텐츠 — `data/`, 기획 문서 |
| **정훈** | 관객 | 채팅 엔진·검증 게이트·데이터 스키마와 로더·채팅 UI 컴포넌트·기획 지원 도구(페르소나 부스·validate)·향후 LLM 통합 — `engine/`, `tools/` |
| **현재** | 무대 | 방송 셸·시청자 경제(수 증감·언락·게임 단위 신선도)·게임 전부·게임↔셸 규격·배포(GitHub Pages) — `games/` |

## 근거

C3 원칙(숫자는 룰이 만들고, AI 시청자는 말만 한다)을 그대로 팀 경계로 사용한다 —
**숫자를 만드는 사람(무대)과 말을 만드는 사람(관객)**. 두 영역은 이벤트 계약
(`docs/contract.md`)에서만 만나므로 병렬 작업이 가능하고, 제품 구조와 팀 구조가 일치한다.
부하는 초반 관객(엔진 추출이 기획 병렬화의 선행 조건) → 중반 무대(게임 반복 생산) →
후반 각 1건씩(무대 = 유저 제작 게임 문법, 관객 = LLM 통합)으로 장기 균형.

## 경계 판정 (사전 합의)

1. **이벤트 발행 코드**: 게임 안에 들어가므로 구현은 무대. 계약 위반 지적 권한은 관객
2. **채팅 UI**: 관객이 컴포넌트로 제공, 무대는 임베드만
3. **게임 단위 신선도**: 시청자 수에 영향을 주므로 룰 = 무대 소속 (관객 아님)

## 공동 소유

`docs/contract.md` (이벤트 스키마·페르소나 데이터 형식) — 이 문서를 바꾸는 PR은
정훈·현재 상호 리뷰 필수. 그 외 각자 영역은 자율.

## 대안 (기각)

- "플랫폼 vs 게임" 분할 — 인프라·CI가 한쪽에 쏠려 소윤 지원 병목 우려로 기각
- 3인 공동 소유 — 에이전트 3대가 서로 다른 진실을 만들 위험이 커서 기각
