# ADR-008 — 방송 장비(Rig) 업그레이드 + §8.4 금지 목록 조건부 개정

- 일자: 2026-08-09
- 상태: **초안 — 팀 검토 전.** 확정된 것 없음. §7 미결 4건이 열려 있다
- 발의: 사용자 지시 — *"방송 장비를 업그레이드할 수 있는 방안을 넣고, 그걸 업그레이드하면
  기본 시청자수를 보장하거나, 시청자 배율이 더 터지거나, 도네이션이 더 자주 터질 수 있는 구조"*
- 관련: 시뮬 레이어 v0.2 §8.4(금지 목록) **개정 대상** · ADR-006(도감·파장·해금) ·
  ADR-007(텐션·표현 축) · `docs/reports/2026-08-08-streaming-sim-genre-review.md` §2-3·§8-4

---

- **무엇을**: 방송 장비 3계열 × Lv0~3. ① 송출기 — 기본 시청자 보장(+250/+600/+1,200)
  ② 조명·무대 — 획득 배율(×1.10/×1.20/×1.32) ③ 도네 알림 — 도네 빈도(간격 ×0.85/×0.72/×0.60,
  확률 +8/+15/+22%p). 레벨업 = **코인 + 부품(미션 보상) + 등급 요구**. 장비는 사는 것이 아니라
  **유지**한다 — 방송당 유지비, 미납 시 조용히 한 단계 강등.
- **왜**: v0.2 §8.4는 "시작 시청자↑·배율↑·임계↓·벌칙↓"을 금지했다. 근거(장르 리뷰 §2-3 —
  Streamer Life Simulator: 업그레이드 포화 = 게임 종료)는 여전히 유효하지만, 사용자가
  강화 구조를 명시 요구했으므로 **금지를 푸는 대신 조건부 허용으로 개정**한다. 조건은 둘 —
  **자기 상쇄**(강화가 평가식의 난이도를 함께 올린다)와 **유지비**(재화가 축적되지 않는다).
- **규칙 준수**: 강화는 **재화(시청자·코인)만 늘리고 명성(등급)은 늘리지 못한다** — 이 분리가
  ADR의 핵심 불변식이다. 세 계열 모두 `gradeShow`에 상쇄 항이 이미 존재하며(§3), 전역
  기대치 세금(§4)이 잔여 인플레를 흡수한다. C3 무관(장비는 무대 소유 룰 수치, 시청자 관여 없음).
  규약 2 유지 — 강등은 무연출.
- **선행 조건**: **§6-1 `start: start0` 수정이 반드시 먼저다.** 이것 없이 송출기 계열을 넣으면
  상쇄가 하나도 안 걸린 채 파워만 들어간다 (§2).
- **미결 (팀)**: §7 참조 — `RIG_TAX`·유지율 실측, 강등 단위, `SUB_BONUS_CAP` 통합 상한,
  §8.4 개정 문구.
- **저장**: `jonggems-channel-v1`에 `rig: {feed, stage, don}`(각 0~3)·`donHist[]`(직전 3회
  도네 수입) 추가. 구 저장분은 전부 0으로 이월.

## 1. 배경 — 왜 금지 목록을 건드리는가

v0.2 §8.4의 금지 목록은 장르 리뷰 §2-3에서 나왔다. SLS 계열의 실질 목표가 장비·집·차
업그레이드였고, 유저 리뷰가 *"기본 업그레이드를 다 사고 나면 반복적이고 너무 쉬워진다"*,
*"후반에는 의미 있는 도전이 없다"*로 수렴했다. **목표를 재화 축적에 걸면 재화가 포화하는
순간 게임이 끝난다.**

이 ADR은 그 위험을 부정하지 않는다. **두 개의 안전판으로 받아낸다.**

| 안전판 | 막는 것 |
|---|---|
| **자기 상쇄** (§3) | 강화가 등급을 밀어 올려 명성이 인플레되는 것 |
| **유지비** (§5) | 코인이 무한 축적되어 "다 사면 끝"이 되는 것 |

## 2. 선행 결함 — 현행 `subBonus`의 상쇄가 작동하지 않는다

```js
shell.js:875   var start0 = g.startViewers + this.subBonus();   // 실제 시작 = 300 + 최대 700
shell.js:1609  Shell.gradeShow({ ..., start: g.startViewers })  // 등급은 300으로 계산
```

`growth = log10(final / start) × 25`는 출발선이 오르면 난이도가 함께 오르도록 설계된
비율 공식이다. 그런데 등급 산정에 **실제 시작값(`start0`)이 아니라 기본값(`g.startViewers`,
300)이 넘어간다.** 분모가 고정이므로 구독자 보너스는 순수 무상 파워다.

**이 ADR의 송출기 계열은 같은 구멍을 공유한다.** §6-1 수정이 선행 조건인 이유다.

## 3. 세 계열의 대가 — 대부분 이미 공식에 있다

| 계열 | 대가 | 근거 | 신규 구현 |
|---|---|---|---|
| 송출기 | 출발선이 높아지면 **같은 등급에 더 큰 최종값**이 필요 | `growth = log10(final/start) × 25` (40점) | **§6-1 수정 필요** |
| 송출기 | 이탈이 비례(0.5%/s)라 **방치 비용도 비례해 커진다** | 기존 코드 | 없음 |
| 조명·무대 | 스파이크가 커지면 peak가 오르고 **유지 점수가 떨어진다** | `hold = final/peak × 20` (20점) | **없음 — 이미 작동** |
| 도네 알림 | 등급 기여가 **로그라 12점에서 포화** | `don = clamp(log10(coins+1)×4, 0, 12)` | 없음 |
| 도네 알림 | 도네 배너 점유가 늘어 **큰 자극이 밀린다** | 규약 3 · `_fxQueue` 0.4초 큐 | 없음 |
| 도네 알림 | 도네 획득분은 단일 태그라 **파장을 만들지 못한다** | ADR-006 | 없음 |

> 조명·무대 계열의 대가가 특히 깔끔하다 — **"터뜨릴수록 유지가 어려워진다"**가 이미
> `hold` 항에 있고, 실제 스트리밍의 현실과도 일치한다. 별도 페널티를 만들 필요가 없다.

## 4. 기대치 정규화 (2차 안전판)

```
score -= RIG_TAX × Σ장비레벨        // RIG_TAX ≈ 1.5 → 만렙(9레벨) −13.5점
```

김 피디 대사로: *"장비가 그 정돈데, 이 정도면…"*

계열 1·3의 상쇄는 공식에 있지만 계열 2는 `hold` 하나만 건드리므로, 전역 세금으로 잔여
등급 인플레를 흡수한다. **재화는 강화로 늘고, 명성은 실력으로만 는다**는 분리를 완성한다.

## 5. 유지비 — 포화를 막는 핵심 장치

> **장비는 사는 것이 아니라 유지하는 것이다.**

```
방송당 유지비 = (직전 3회 평균 도네 수입) × 유지율
유지율       = Σ장비레벨 × 6%          // 만렙 9레벨 = 54%
미납 시      → 장비 한 단계 강등 (조용히 — 규약 2, 손실 무연출)
```

파라미터가 **6% 하나**이고 채널 규모를 자동 추종하므로 절대값 튜닝이 필요 없다
(주요⑥ 튜닝 표면 동결 준수).

효과:

- **코인이 무한 축적되지 않는다** → §2-3 함정(다 사면 게임 종료)이 구조적으로 발생 불가
- **도네 장비를 올리면 수입도 늘지만 유지비도 늘어 순이익이 자동 조정**된다
- 만렙이 종착점이 아니라 **만렙을 유지하는 것이 새 목표**가 된다
- 서사적으로 정확하다 — 스트리머의 장비 욕심 vs 고정비

## 6. 사양

### 6.1 효과 (Lv0 = 미보유)

| 계열 | 효과 | Lv1 | Lv2 | Lv3 |
|---|---|---|---|---|
| **송출기** | 기본 시청자 보장 (시작 시청자 가산) | +250 | +600 | +1,200 |
| **조명·무대** | 획득 배율 (`gain()` 증폭, 도네 제외) | ×1.10 | ×1.20 | ×1.32 |
| **도네 알림** | 도네 빈도 (재장전 배율 · 발생 확률 가산) | ×0.85 · +8%p | ×0.72 · +15%p | ×0.60 · +22%p |

도네 기준선이 `donT = 8 + rand×7`, 확률 `0.5`이므로 Lv3에서 **간격 4.8~9초 · 확률 72%**.

### 6.2 획득

| 레벨 | 코인 | 부품 | 요구 등급 |
|---|---|---|---|
| Lv1 | 1,500 | 2 | — |
| Lv2 | 6,000 | 5 | 실버 (tier 1) |
| Lv3 | 20,000 | 9 | 골드 (tier 2) |

**부품은 미션 보상에서만 나온다. 코인으로 살 수 없다.** 이 제약을 풀면 도네(랜덤 파생)가
강화 속도를 정하게 되어, 장르 리뷰 §8-4 D-2(랜덤이 실력을 추월)가 강화 축에서 재발한다.
등급 요구가 있으므로 **명성이 장비의 상한을 정한다** — "재화와 명성으로 다음 미션"의 실체.

### 6.3 코드 삽입 지점

| # | 위치 | 변경 |
|---|---|---|
| **1** | `shell.js:1609` | **`start: g.startViewers` → `start: start0`** — §2 결함 수정. **선행 조건** |
| 2 | `shell.js:875` | `start0 = g.startViewers + subBonus() + Rig.floor()` |
| 3 | `stage.gain()` | `actual = n × freshMult × Rig.gainMult()`. **도네 획득에는 미적용** (§6.4와 이중 계상 방지) |
| 4 | 게임 5종 `donT` | **셸 소유로 이관 — §6.4 참조** |
| 5 | `Shell.gradeShow` | `score -= RIG_TAX × ΣLv` |
| 6 | 정산(`settleShow` 부근) | 유지비 차감 + 미납 시 강등 + `donHist` 갱신 |
| 7 | `Shell.shopBuy` 옆 | `Shell.rigUp(ch, line)` **순수 함수** — 차감·중복·등급 잠금·잔액 검사 |

### 6.4 계약 변경 — 도네 주기를 셸이 소유한다

현재 게임 5종(`hwaryeok`·`bomb`·`fishing`·`giving-up`·`pocket`)이 전부 아래를 복붙하고 있다:

```js
st.donT = 8 + Math.random() * 7;
if (Math.random() < .5) { ... stage.gain(d, '익명의 도네', 'donation'); }
```

장비가 이 주기를 바꾸려면 게임 5개를 모두 고쳐야 한다. **`contract.md` 4.2에
`stage.donRoll()`을 올리고 셸이 도네 주기를 소유**하는 것이 맞다 — 새 게임이 추가돼도
장비가 공짜로 따라온다. `contract.md`는 공동 소유이므로 정훈·현재 상호 리뷰 대상
(ADR-005 완화 기간이 만료됐다면 원 규약 적용).

### 6.5 §8.4 개정안 (v0.2 반영 대상)

```
현행: 금지 목록 — 시작 시청자↑ · 보상 배율↑ · 언락 임계↓ · 실패 벌칙↓

개정: 위 4종은 원칙적으로 금지한다. 다음 두 조건을 모두 증명한 강화만 예외로 허용한다.
      (a) 자기 상쇄 — 그 강화가 gradeShow의 난이도를 함께 올린다는 것을 공식으로 보일 것
      (b) 유지비   — 그 강화가 재화를 소모시켜, 재화 포화가 게임 종료로 이어지지 않을 것
      언락 임계↓ · 실패 벌칙↓는 (a)를 만족시킬 수 없으므로 **무조건 금지로 남는다.**
```

## 7. 미결 · 검증

### 7.1 미결 (팀 결정 필요)

1. **`RIG_TAX` 1.5 · 유지율 6%는 미검증 초기값** — 현행 도네 수입(`_showCoins`) 실측 후 확정
2. 유지비 미납 강등을 **계열별**로 할지 **전체 1단계**로 할지
3. 송출기 Lv3(+1,200) + `SUB_BONUS_CAP`(700) = 1,900이 언락 페이싱 전제를 깨는지 —
   **통합 상한** 도입 검토
4. §6.5 개정 문구를 v0.2 §8.4에 반영 (문서 소유 = 공동)

### 7.2 검증 (selftest 추가)

- `Shell.rigUp` 순수 함수 — 차감·중복·등급 잠금·잔액 부족 4케이스
- **유지비 발산 검사** — 만렙에서 도네 수입 < 유지비가 되는 구간이 없는지.
  있으면 강등 나선(강등 → 수입 감소 → 재강등)에 빠진다
- **등급 인플레 검사** — Lv0 vs 만렙에서 **같은 실력의 봇이 같은 등급을 받는가**.
  장르 리뷰 §7의 Playwright 숙련 봇 하네스로 측정 가능. 이 ADR의 핵심 불변식
  ("재화는 늘고 명성은 안 는다")의 유일한 직접 검증
- 조명 배율 ×1.32에서 `hold` 하락폭 실측 — **상쇄가 과하면 배율이 손해가 된다**
- 기존 selftest 회귀 — 특히 `unlockState`·`campaign` 순수 함수
