> **공동 소유 문서.** 이 문서를 바꾸는 PR은 정훈·현재 상호 리뷰 필수 (ADR-001).

# 1. 이벤트 스키마 (v1 초안 — 관객 소유)

게임(무대)이 발행하고 채팅(관객)이 소비하는 단위. 게임별 어휘 파일 `data/events/<id>.js`
(2026-08-09 games/<id>/chat-data.js에서 이관 — ADR-002의 JSON 리터럴은 아니고 기존
`window.*_CHAT` JS 리터럴 그대로, 캐리어 원리는 동일)가 이 스키마의 인스턴스다.

```js
T[ev] = {
  facts:  ['{slot}을 포함한 사실 템플릿', ...],   // 버스트의 첫 줄 — 수치 앵커
  flavor: [['tone', '리액션 문장'], ...],          // 나머지 줄 — 톤별 리액션
};
BURST[ev] = 1..4;                                  // 버스트 무게 (기본 1)
```

**규칙** (어긴 것은 selftest·validate가 잡는다):

- 이벤트 이름은 소문자 스네이크 케이스. `start`·`end`는 필수, `donation`·`milestone`·`idle`은
  권장 공용 이벤트 (셸의 캠 표정 매핑 `CAM_MOOD`를 공짜로 얻는다 — 4.6절 참고)
- **사실 슬롯 계약**: 게임이 `emit(ev, facts)`으로 넘기는 facts의 **모든 값이 발화 본문에
  표시 포맷 그대로**(예: `toLocaleString()` 결과) 포함되어야 검증을 통과한다
- 따라서 **한 이벤트의 사실 템플릿들은 전부 같은 슬롯 집합을 써야 하고**, 그 집합은 게임이
  emit하는 facts 키 집합과 일치해야 한다 — 다르면 사실 줄이 확률적으로(최악엔 상시)
  폐기된다 (2026-08-07 pocket 4종에서 실제 발생, selftest에 정합 검사 추가됨)
- flavor는 이벤트당 **6개 이상** (비반복 게이트 <0.72의 전제), 톤은 3절의 공인 6종만
- 사실 줄은 LLM을 쓰지 않는다 — 수치 정확성은 게이트로 거르는 게 아니라 템플릿으로 보장

# 2. 페르소나 데이터 형식 (v1 초안 — 관객 소유, 값 저작은 기획)

현행 구현(`games/shell/chat.js`의 `PERSONAS`)의 명문화. 캐스트는 전 게임 공유 8종.

```js
{ nick: '불멍장인', color: '#ff8d5a', tones: ['hype', 'mock'], arch: 'thrill' }
```

- `tones`는 3절 6종의 부분집합 — 페르소나는 자기 톤이 달린 템플릿만 말한다 (성격의 실체)
- `arch`는 소속 경제 원형 (공명 판정층 ADR-004 §7.2 다대일 매핑 — `thrill`/`fan`/`expert`/`casual`).
  **발화 캐스팅 가중치에만** 쓰인다 — 경제(관객 구성)가 누가 말할지를 정하는 단방향 (C3 유지).
  누락 시 캐스팅은 균등 폴백으로 동작한다 (침묵하지 않는다)
- 설계 시트(정체성·동기·말투·LLM 프로필 초안)는 `prototypes/05-hwaryeok-personas.md`가 원본.
  신규 페르소나는 시트의 3축 덮개(위험 선호/정보 깊이/애정 온도) 자리를 명시할 것
- **v2 예약 필드** (공명 모델 — `docs/resonance-model.md` §5 게이트 통과 후):
  `interest`(흥미도 벡터) · `valence`(호오) · `threshold`(발화 임계) — 판정층 데이터는
  빌드 타임 정적이며 런타임에 LLM 출력으로 생성·수정될 수 없다
- **이관 완료 (2026-08-09)**: 값은 `data/personas/cast.js` — `window.JONG_CAST = [...]`
  대입문의 우변이 엄격한 JSON 리터럴인 .js 캐리어다. 순수 .json이 아닌 이유는 `file://`
  제약 (fetch가 CORS로 막힌다 — ADR-002). validate가 우변을 JSON.parse로 검사하므로
  JSON으로서의 형식은 유지된다. 값 저작은 소윤, 스키마·로더는 관객,
  경제 관여 필드가 생기면 clamp 범위는 무대가 검증

# 3. 톤 목록 (v1 — 확정)

`hype`(흥분·환호) · `worry`(걱정·재촉) · `info`(분석·훈수) · `mock`(조롱·드립) ·

# 6. 티키타카·관계 변수 데이터 (v1 — 관객 소유, 값 저작은 기획, ADR-003)

`data/tikitaka.js` — `window.JONG_TIKITAKA = { pairs, moments }` (ADR-002 JSON 캐리어).
**발화층 연출 전용** — 공명 모델(판정층, `docs/resonance-model.md`)의 도입 게이트와 무관하고,
경제·룰 수치에 관여하지 않는다 (C3 유지).

```js
pairs:   [{ from, to, chance, lines: [['tone', '응답'], ...] }]  // 2홉: from의 발화가
         // 화면에 나가면 chance 확률로 to가 받아친다. 응답은 재트리거 없음(2홉 정지),
         // 쿨다운 2.5초, 같은 verify 게이트 통과 필수. lines ≥ 6, 톤은 to의 tones 안
moments: [{ nick, trust, line: ['tone', '발화'] }]               // 관계 변수 1회성 발화
```

관계 변수(trust)는 큰 사건(버스트 무게 ≥3)마다 1 누적되는 localStorage 스칼라
(`jgs-rel-v1`, 방송 간 유지). moments는 임계 돌파 시 한 번만 말한다 —
"냉정한미식가의 첫 인정" (페르소나 시트 4.5 우선순위 2).

# 7. 반응 도감·캐스트 해금 데이터 (v1 — 공동 소유, 값 저작은 기획, ADR-006)

`data/dex.js` — `window.JONG_DEX = { base_triggers, unlocks }` (ADR-002 JSON 캐리어).
판정·해금 로직은 `games/shell/dex.js`(무대), 데이터 스키마는 관객, 값은 기획 소유.
시뮬 레이어 v0.2 §5·§8의 최소 실장 — **칸 = (개체, 태그)** (2026-08-09 태그 승격, ADR-006 예고분).
이벤트 → 태그 번역은 `data/events/tagmap.js`(v0.2 §6.2 초안, §11.2-2 미결)가 맡고,
판정층 로스터에는 100종 데이터(`data/personas/viewers.js`)의 **불멸 관측단 12종**이
발화 없이 합류한다 (발화층/판정층 분리 — `data/personas/README.md`).

```js
base_triggers: { "닉": ["태그", ...] }            // 기본 캐스트 8종의 반응 칸 (36태그)
unlocks: [{ nick, color, tones, arch,             // cast.js와 같은 페르소나 스키마 +
            cost: { subs?, coins? },              // 해금 비용 — 구독자(시청자 파생)·코인(도네 파생) 소비
            triggers: [...], repellents: [...],   // 반응 칸 — tagmap이 발행하는 36태그만 (validate가 도달 가능성 검사)
            desc }]
```

**규칙**: 칸은 이벤트 발생 + 결정론 판정이 연다 — 발화 성공 여부 무관 (C3b). 파장(방송당
신규 칸 수)은 구독자 전환에만 곱해진다: `× (1 + 0.15 × min(파장, 8))` — 방송 중 시청자 수
무관여. 해금은 선택지 개방만 — 시작 시청자↑·배율↑·임계↓·벌칙↓ 금지 (v0.2 §8.4).
저장: localStorage `jgs-dex-v1`.

# 4. 게임↔셸 인터페이스 (v0.1 — 무대 소유, 구현 완료)

구현: `games/shell/shell.js`. 이 문서와 구현이 어긋나면 **이 문서가 맞다**.
게임 2종(`games/hwaryeok/`, `games/giving-up/`)이 이 계약만으로 돌아가는 것으로 검증됨.

## 4.1 게임이 셸에 등록하는 것

```js
Shell.register({
  id:           'hwaryeok',       // 고유 키. 신선도·최고 기록의 저장 키가 된다
  title:        '화력쇼',
  tagline:      '…',              // 허브 카드 한 줄 소개
  duration:     180,              // 방송 길이(초). 셸이 카운트다운하고 0에서 종료시킨다
  startViewers: 300,              // 방송 시작 시청자
  usesChain:    true,             // 연쇄 배수 미터를 띄울지
  chat:         { T, BURST },     // 이 게임의 이벤트 어휘 (1절 스키마)
  foot:         '<html>',         // 화면 하단 조작 안내
  start(stage)  → instance        // 방송 1회분 인스턴스를 만든다
  preload()                       // (선택) 방송 준비 화면 진입 시 호출 — 게임 아트 지연 로드 트리거
});
```

`start()`는 **방송을 시작할 때마다** 호출된다. 게임은 여기서만 상태를 만들고, 인스턴스 밖으로
전역 상태를 남기지 않는다 — 남기면 두 번째 방송이 첫 방송을 물려받는다.

`preload()`는 선택이다. 이미지가 있는 게임은 파싱 시점에 내려받지 말고 여기서 시작하라 —
첫 화면이 전 게임의 아트를 전부 내려받으면 안 된다. 카운트다운(~2.4초)이 로드를 가리고,
그래도 늦은 이미지는 게임 자신의 벡터 폴백이 받아야 한다 (아트는 얹는 층이지 의존성이 아니다).
여러 번 불려도 안전해야 한다 (no-op 가드).

## 4.2 셸이 게임에 주는 것 (`stage`)

| 멤버 | 설명 |
|---|---|
| `ctx`, `W`, `H` | 960×430 캔버스 2D 컨텍스트. 배경 클리어·흔들림·비네트·플래시는 셸이 처리한다 |
| `panel` | 캔버스 아래 조작 UI용 `HTMLElement`. 게임이 내용을 전적으로 소유한다 |
| `viewers` (읽기) | 현재 시청자 수 |
| `timeLeft` (읽기) | 남은 방송 시간(초) |
| `now` (읽기) | 방송 시작 이후 경과 시간(초) — 애니메이션 위상용 |
| `live` (읽기) | 방송 진행 중인가. **시청자를 잃은 뒤 루프를 계속 돌리면 안 된다** |
| `gain(n, label, ev)` | 시청자 획득. **신선도 배수와 방송 장비 배율(ADR-008 조명·무대)을 곱한 실제 반영량을 반환한다** — 표시·채팅에는 반환값을 쓸 것. 장비 배율은 `ev === 'donation'`에는 걸리지 않는다 (도네 알림 계열과 이중 계상 방지). `label`이 있으면 FX 팝업, 없으면 조용히. `ev`(선택)는 **총량이 아니라 원형별 배분에만** 쓰인다 — 그 이벤트의 자극 벡터(`chat-data.js`의 `STIM`)로 누가 유입될지 정한다. 생략하면 중립 배분(현재 구성비대로)이라 기존 호출은 그대로 동작한다 (ADR-004) |
| `lose(n)` | 시청자 손실. 연출·효과음 없음(규약 2). 0명이 되면 셸이 방송을 끝낸다 |
| `donRoll(dt, base, prob)` | **랜덤 도네 1틱.** 타이머·확률·금액·`gain`·`emit('donation')`을 셸이 전부 처리한다. `base`(재장전 기준 초, 기본 9)와 `prob`(발생 확률, 기본 .45)는 게임이 정한다. 터졌으면 실제 반영량, 아니면 `0`을 반환 — 효과음이 필요하면 반환값으로 분기할 것. **게임이 직접 도네 타이머를 굴리지 말 것**: 방송 장비(ADR-008)가 빈도를 조절하려면 한 곳이어야 하고, 그래야 새 게임도 장비를 공짜로 따라온다. 금액 산식(규모 비례 1~3%·최소 10명)은 셸 소유 (규약 5 — 양념이 뼈대를 넘보지 않게) |
| `emit(ev, facts)` | 채팅 이벤트 발행. 어휘에 없는 `ev`는 조용히 무시된다 |
| `hud(html)` | 뷰포트 좌상단 명판 내용 |
| `stamp(text)` / `ticker(text, muted)` | 대형 스탬프 / 하단 한 줄. `muted`는 손실 고지용(무연출) |
| `setChain(v)` | 연쇄 배수 미터 갱신 (`usesChain: true`인 게임만) |
| `shake(v)` / `flash(v)` | 화면 흔들림·화이트 플래시 요청 (감쇠는 셸이) |
| `end(reason)` | 게임 쪽 사유로 방송 종료. `reason`: `'clear'` 등 |

## 4.3 게임이 셸에 돌려주는 것 (`instance`)

| 멤버 | 필수 | 설명 |
|---|---|---|
| `step(dt)` | ✔ | 초 단위 `dt`. 방송 중에만 호출된다 |
| `draw(ctx, dt)` | ✔ | 흔들림 변환이 적용된 상태로 호출된다. 배경 클리어 불필요 |
| `key(e)` | | `keydown`. 셸이 `Escape`(중단)와 리피트 키를 먼저 걸러낸다 |
| `pointer(p, type, e)` | | `p`는 캔버스 좌표(0..960, 0..430)로 변환되어 들어온다 |
| `summary()` | | 정산 화면에 넣을 `[라벨, 값]` 배열 |
| `dispose()` | | 방송이 끝날 때 — 붙인 리스너를 여기서 뗀다 |

`step`/`draw`에서 예외가 새어 나오면 셸이 잡아 방송사고(`'crash'`)로 정산하고 인스턴스를
버린다 — 방송(rAF 루프)은 죽지 않는다. 이것은 최후 방어선이지 게임이 기대는 동작이 아니다.

## 4.4 소유권 경계 (어기면 규약이 깨진다)

- **시청자 수는 셸만 바꾼다.** 게임은 `gain`/`lose`로 요청만 한다 — 규약 1의 단일 수치를
  게임이 직접 만지면 체력·점수·통화 셋이 갈라진다
- **게임 단위 신선도는 셸 소유.** 게임 내부 신선도(화력쇼의 사고 유형별, GUOI의 추락)는
  게임 소유이고, 둘은 곱해진다
- **채팅은 룰 수치에 관여하지 않는다 (C3).** `emit`은 단방향이다 — 반환값이 없고, 채팅 결과가
  게임 상태로 되돌아오는 경로는 존재하지 않는다
- **큰 자극은 셸의 0.4초 FX 큐를 통해서만** (규약 3). 게임이 자체 팝업을 만들지 않는다

## 4.5 새 게임 추가 절차

1. `data/events/<id>.js` — 이벤트 어휘 (소윤 협의, `window.<ID>_CHAT = { T, BURST }`)
2. `games/<id>/game.js` — `Shell.register(...)`
3. `index.html`에 `<script>` 두 줄 추가

셸·다른 게임은 건드리지 않는다. 건드려야 한다면 계약이 부족한 것이므로 이 문서를 먼저 고친다.
