## 1. 평가 프레임워크 선정

### 1.1 검색으로 확인한 프레임워크

| 프레임워크 | 출처 | 무엇을 재는가 | 본 평가 적용 |
|---|---|---|---|
| **PersonaGym / PersonaScore** | Samuel, Zou, Zhou, Chaudhari, Kalyan, Rajpurohit, Deshpande, Narasimhan, Murahari — Findings of EMNLP 2025 (arXiv 2407.18416) | 페르소나 에이전트가 배정된 페르소나를 얼마나 충실히 연기하는가. 결정이론 기반 5과제 | **Tier B**(런타임) |
| Self-BLEU4 / TF-IDF Diversity | OpenHospital (arXiv 2603.14771) | 합성 페르소나 집단의 텍스트 구별도 | Tier A |
| ARI / Centroid Distance | Scaling Law in LLM Simulated Personality (arXiv 2510.11734) | 페르소나 프로파일의 식별가능성 | Tier A |
| Uniqueness 1–5 | DeepPersona (arXiv 2511.07338) | LLM 판정 기반 개체 독창성 | Tier B |
| Persona Drift 축 투영 | Lu et al. 2026 등 | 세션 진행 중 페르소나 이탈 | Tier B |

### 1.2 PersonaGym의 5과제

결정이론의 세 갈래에 각각 대응합니다.

| 과제 | 이론 갈래 | 내용 |
|---|---|---|
| Expected Action | 규범적 | 그 페르소나가 취할 법한 행동을 선택하는가 |
| **Linguistic Habits** | 규정적 | 어휘·구문·어조가 페르소나에 맞는가 |
| Persona Consistency | 규정적 | 직접 질문받을 때 속성을 유지하는가 |
| Toxicity Control | 규정적 | 도발적 프롬프트에 적절히 대응하는가 |
| Action Justification | 서술적 | 행동의 이유를 페르소나답게 설명하는가 |

<cite index="10-1">PersonaScore는 인간 판정과 강하게 상관합니다 — 세 모델 평균 Spearman 75.1%, Kendall-Tau 62.73%, 주석자 간 Fleiss' Kappa 0.71</cite>. 신뢰할 만한 기준입니다.

### 1.3 왜 두 단계로 나누는가

PersonaGym은 **"LLM이 페르소나를 연기한 결과"**를 평가합니다. 현재 100개는 아직 연기되기 전의 **명세(스펙)**입니다. 명세에 PersonaGym을 그대로 돌릴 수 없으므로 다음과 같이 분리합니다.

- **Tier A — 정적 명세 평가** (지금 수행 가능): 다양성·커버리지·식별가능성·설계 의도 정합성
- **Tier B — 런타임 연기 평가** (구현 후 수행): PersonaGym 5과제 적용

본 리포트는 Tier A를 실측하고, Tier B의 프로토콜을 §5에 정의합니다.

## 2. `line` 필드 재검토 — 핵심 지적

### 2.1 결론: 변형 불가능한 형태다

v0.1의 `line`은 페르소나당 고정 문자열 1개입니다. 세 가지 구조적 결함이 있습니다.

**결함 A — 증식 시 변이 규칙이 없다**
설계 문서 §5.3의 자식 생성 규칙은 `x`, `y`, `triggers`, `arrival`만 변이시킵니다. `line`은 언급조차 없습니다. 부모의 문장이 그대로 상속되면, 세대가 지날수록 **같은 문장을 치는 개체가 기하급수적으로 늘어납니다.** 100명이 자란 채팅창이 복사-붙여넣기처럼 보이게 되며, 이는 시스템의 최종 산출물(가상 채팅 로그)을 직접 망가뜨립니다.

**결함 B — 상황 분기가 없다**
흥미 급상승, 지루함, 도네이션 순간, 이탈 직전은 전혀 다른 발화를 요구합니다. 문장 하나로는 LLM이 그 문장을 그대로 되뱉거나(에코), 무시하고 일반적 말투로 흘러갑니다.

**결함 C — 실측된 결손 2건**
`V-009 은근한후원자`와 `V-022 조용한자부심`의 `line`이 빈 문자열입니다. 프롬프트 템플릿의 `"{line}"`이 `""`로 렌더링되어 어투 앵커가 소실됩니다.

### 2.2 이것이 중요한 이유 — PersonaGym 실증

<cite index="10-1">Linguistic Habits는 5개 과제 중 가장 어려운 과제로, 3개 최신 모델(GPT-4.1, GPT-4.5, DEEPSEEK-V3)을 제외한 모든 모델이 4.0 미만을 기록했습니다. LLaMA-2-13B에서 70B로 가도 거의 개선되지 않았고, GPT-3.5가 LLaMA-2-13B보다 낮은 유일한 과제였습니다</cite>(3.63 vs 3.77).

<cite index="10-1">논문의 불일치 사례도 정확히 이 지점입니다. "22세 런던 작가" 페르소나에서 PersonaGym은 4.5/4.5/4.0을 줬으나 인간 평가자는 2.0/2.0/3.0을 줬습니다. LLaMA-2-70B만 영국식 표현을 썼고, 모든 응답이 작가에게 기대되는 세련된 언어를 결여했기 때문입니다</cite>.

즉 **어투 재현은 LLM이 가장 못하는 영역이며, 예시 문장 하나로는 절대 부족합니다.** 100개 페르소나의 구별은 좌표가 아니라 말투에서 체감되므로, 이 필드가 가장 약한 고리입니다.

### 2.3 개선안: `line` → `speech` 구조 전환

```json
"speech": {
  "register": "measured",
  "endings": ["~잖아", "~이잖아"],
  "lexicon": ["시너지", "덱", "정석"],
  "quirks": ["스트리머가 아니라 판을 향해 말한다"],
  "exemplars": {
    "spike": null, "valley": null, "donate": null,
    "exit": null, "observe": "그 카드 왜 안 집었지, 시너지 보이잖아"
  },
  "mutation": { "endings": 0.12, "lexicon": 0.15, "quirks": 0.06 }
}
```

| 필드 | 역할 | 변형 방식 |
|---|---|---|
| `register` | 어조 계층 (measured/casual/shout/minimal, formal 접두) | 증식 시 인접 계층으로 이동 |
| `endings` | 종결 패턴 | `mutation.endings` 확률로 교체·추가 |
| `lexicon` | 고빈도 어휘 (트리거에서 파생) | 트리거가 변이하면 자동 연동 |
| `quirks` | 발화 습관 | `mutation.quirks` 확률로 1개 교체 |
| `exemplars` | 상황별 예시 5슬롯 | **런타임에 LLM이 프로파일로부터 생성** |
| `mutation` | 변이 계수 | 혼돈·발화량 성향에서 자동 산출 |

**핵심은 `exemplars`가 대부분 `null`이라는 점입니다.** 이것은 결함이 아니라 설계입니다. 고정 문장을 미리 다 써두면 다시 변형 불가능해집니다. 대신 `register + endings + lexicon + quirks`가 **생성 규칙**이 되고, 상황이 발생했을 때 LLM이 그 규칙으로 문장을 만들어냅니다. 기존 `line`은 그 페르소나의 대표 상황 슬롯에 앵커로 남겨 생성 방향을 잡아줍니다.

`mutation` 계수는 개체마다 다릅니다 — 혼돈 성향과 발화량이 높을수록 말투가 잘 변합니다. 실측 범위는 `endings` 0.11~0.39, `lexicon` 0.09~0.33, `quirks` 0.05~0.20입니다.

## 3. Tier A 정량 평가 결과

### 3.1 사분면 균형 및 좌표 분포

```
사분면 분포: Q1 25 / Q2 25 / Q3 25 / Q4 25          ✅ 완전 균형
x 범위 -0.95 ~ +0.96, 평균 +0.030, 표준편차 0.685    ✅ 편향 없음
y 범위 -0.96 ~ +0.96, 평균 +0.007, 표준편차 0.663    ✅ 편향 없음
```

5×5 격자 점유 (상단 = y+):

```
     4  7  3  6  8
     6  5  0  1  8
     2  0  0  0  2      ← 중앙 행 거의 공백
     8  3  0  4  7
     7  5  2  2 10
점유 20/25 (80%), 중앙부(|x|<0.2 & |y|<0.2) 개체: 0
```

**결함 발견 — 중앙 결손.** 빈 5칸이 전부 중앙부에 몰려 있고, 미온적 중도 시청자가 **한 명도 없습니다.** 실제 방송 시청자의 상당수는 특별한 성향 없이 그냥 틀어놓는 층이며, 이들이 없으면 군집 시뮬레이션이 과도하게 극단적으로 반응합니다.

이는 Bisbee et al.(2024)이 경고한 "분포 꼬리 과소대표"의 **정반대 문제**입니다. 극단을 의도적으로 강제했더니 중앙이 사라졌습니다. 양쪽 다 편향입니다.

> **권고**: v0.3에서 중앙부 개체 8~12종을 추가하거나, 초기 개체군 생성 시 좌표를 재샘플링하십시오. 다만 개체 수를 100에서 늘리는 것은 토큰 예산과 직결되므로, 기존 개체 중 8종을 중앙으로 이동시키는 편이 낫습니다.

### 3.2 개체 간 거리 — 설계 기준 자체의 오류

```
최근접 이웃 거리: 최소 0.054 / 평균 0.107 / 중앙값 0.102
거리 < 0.35인 쌍: 525건
```

설계 문서 v0.1의 `replicate()`는 "최소 축간 거리 0.35 미만이면 폐기"라고 규정했습니다. **실측치는 이 기준을 전면 위반합니다.**

그런데 이는 데이터의 잘못이 아니라 **기준의 잘못**입니다. 2×2 좌표 공간에 N개를 균등 배치할 때 이론적 평균 최근접 거리는 약 `0.5/√N`입니다. N=100이면 0.05 — 실측 최소값 0.054는 이론 하한에 거의 근접한 값이며, 평균 0.107은 그 두 배로 오히려 여유가 있습니다.

0.35라는 숫자는 N=8을 가정하고 쓴 것입니다(N=8일 때 이론값 0.177이므로 타당). N=100에 그대로 적용한 것이 오류입니다.

> **수정**: 직교성 기준을 `d_min = 0.5/√N`로 스케일하십시오. N=8 → 0.177, N=16 → 0.125, N=100 → 0.05.

### 3.3 설계 의도 검증 — 파라미터 상관 (Spearman)

|  | x | y | arrival | patience | donate | spawn | volume |
|---|---|---|---|---|---|---|---|
| **x** | 1.00 | **0.08** | −0.44 | −0.65 | 0.15 | 0.54 | 0.59 |
| **y** | 0.08 | 1.00 | −0.64 | −0.29 | **0.86** | **−0.32** | 0.34 |
| arrival | −0.44 | −0.64 | 1.00 | 0.33 | −0.69 | 0.02 | −0.45 |
| patience | −0.65 | −0.29 | 0.33 | 1.00 | −0.25 | −0.53 | −0.71 |
| donate | 0.15 | 0.86 | −0.69 | −0.25 | 1.00 | −0.35 | 0.24 |
| spawn | 0.54 | −0.32 | 0.02 | −0.53 | −0.35 | 1.00 | 0.35 |
| volume | 0.59 | 0.34 | −0.45 | −0.71 | 0.24 | 0.35 | 1.00 |

**✅ 검증 통과**
- **x–y 상관 0.08** — 두 축이 사실상 직교합니다. 4분면 설계의 전제가 성립합니다.
- **donate ~ y = 0.86** — "Y축(사람↔판)이 도네이션을 지배한다"는 설계 주장이 강하게 확인됩니다.
- **patience ~ x = −0.65** — "혼돈 지향일수록 인내심이 낮다"가 확인됩니다.

**❌ 검증 실패 — 증식 축 오귀속**
설계 문서는 "판측(Y−)이 클립·정보 공유로 흥미를 표출한다"고 주장했습니다. 실측은 다릅니다.

```
spawn ~ y = −0.32   (약함)
spawn ~ x = +0.54   (더 강함)
```

증식을 지배하는 것은 Y축이 아니라 **X축(혼돈 지향)**입니다. 원인은 Q3(혼돈×사람)의 spawn이 전 사분면 최고(0.94, 0.96, 0.98 등)라서 Y축 상관을 상쇄했기 때문입니다.

이것은 데이터 오류가 아니라 **설계 주장이 틀렸던 것**입니다. 실제 스트리밍에서도 신규 유입을 만드는 것은 "분석 정보"보다 "충격적인 클립"이며, 실측이 이 현실을 반영하고 있습니다.

> **수정**: 설계 문서 §2.2의 "Y축이 도네이션 총액과 신규 유입의 비율을 지배한다"를 **"Y축은 도네이션을, X축은 신규 유입을 지배한다"**로 정정하십시오. 이는 게임 설계 함의도 바꿉니다 — **바이럴을 원하면 혼돈 이벤트를, 수익을 원하면 사람 서사를 설계해야 합니다.**

### 3.4 이벤트 어휘 커버리지

```
태그 사용률: 36/36 (100%)          ✅ 미사용 태그 없음
사용 엔트로피: 5.03 bits (최대 5.17) ✅ 균등도 97%
2회 이하 사용 태그: 0건             ✅
최다 사용: no_stakes(32), idle(19), numbers_revealed(19), clean_execution(16), rng_jackpot(16)
```

어휘 설계는 문제없습니다. `no_stakes`가 32회로 최다인 것은 자연스럽습니다 — 위험 없는 구간은 거의 모든 시청자가 싫어합니다.

### 3.5 트리거 집합 중복 — 결함 발견

```
v0.1: 완전 동일 트리거 집합 10쌍 (20개 개체가 이벤트 반응 구별 불가)
      Jaccard ≥ 0.5 쌍: 214건 / 4,950쌍 (4.3%)
```

동일 집합 10쌍은 명백한 결함입니다. 예를 들어 `V-004 도전기록원`과 `V-005 클리어각서`는 트리거가 완전히 같아, 흥미도 계산상 좌표 차이만 남고 반응 패턴이 동일합니다.

**v0.2에서 10쌍 중 9쌍을 해소했습니다** (같은 계열 내 태그 1개 교체). Jaccard ≥ 0.5는 214 → 213으로 거의 줄지 않았는데, 이는 **3원소 집합에서 2개를 공유하면 자동으로 Jaccard 0.5**가 되기 때문입니다. 구조적 한계이며, 트리거를 3→4개로 늘리지 않는 한 개선되지 않습니다. 4.3%는 허용 범위로 판단합니다.

### 3.6 텍스트 다양성

```
Self-BLEU4 (문자 4-gram 근사): 0.0140    ← OpenHospital 기준 0.4111
TF-IDF Diversity:              0.9856    ← OpenHospital 기준 0.8727
최고 유사쌍: "최초 순간만 보러 왔습니다" ↔ "판세 뒤집히는 그 순간만 보러 옵니다" (0.42)
```

수치상으로는 참조 연구를 크게 상회합니다. **다만 이 비교는 그대로 받아들이면 안 됩니다.** OpenHospital의 수치는 환자 프로파일 전문(全文)에 대한 것이고, 여기서는 16자 내외의 단문 하나씩입니다. 짧은 텍스트는 자동으로 중복이 적게 나옵니다. **유리한 조건에서 나온 값이므로 우수성의 근거로 쓰지 마십시오.**

실제로 문제가 되는 지표는 따로 있습니다.

```
종결부 분포: '니다' 21건(21%), '는데' 6, '인데' 4, '하다' 3, '했다' 3 …
```

**21%가 격식체 종결로 획일화되어 있습니다.** 인터넷 방송 채팅에서 5명 중 1명이 "~니다"로 말하지는 않습니다. 이는 §2에서 지적한 `line`의 구조적 문제가 표면화된 것으로, `speech.register`를 도입한 v0.2에서 다음과 같이 분화됩니다.

```
casual 31 / measured 25 / formal_casual 15 / shout 12 / formal_measured 8
minimal 5 / formal_shout 3 / formal_minimal 1
고유 종결 패턴: 113종 (개체당 평균 1.7개)
```

### 3.7 식별가능성 (ARI)

파라미터 벡터를 KMeans(k=4)로 군집화하고 사분면 라벨과 비교했습니다.

| 입력 | ARI | 해석 |
|---|---|---|
| 좌표(x, y)만 | **1.000** | 순환논증. 사분면이 좌표로 정의되므로 당연 |
| 전체 7개 파라미터 | 0.827 | — |
| **좌표 제외, 행동 파라미터만** | **0.660** | **이것이 진짜 지표** |

`arrival`, `patience`, `donate`, `spawn`, `volume`만으로 사분면의 66%가 복원됩니다. 좌표를 보지 않아도 행동만으로 어느 사분면인지 상당 부분 판별된다는 뜻이며, **행동 파라미터가 축에서 제대로 파생되었다는 증거**입니다.

1.0이 아닌 것은 오히려 정상입니다. 완전 복원되면 행동 파라미터가 좌표의 결정론적 함수라는 뜻이고, 그러면 별도 필드로 둘 이유가 없습니다.

### 3.8 명세–데이터 정합성 — 결함 발견

**불멸 관측자 지정 오류.** 설계 문서 §7은 "각 사분면 최외곽 개체 3종을 불멸 관측자로 지정"하라고 규정했으나, v0.1의 `immortal_observers`는 이를 따르지 않았습니다.

| 사분면 | v0.1 지정 | 실제 최외곽 3종 | 일치 |
|---|---|---|---|
| Q1 | V-001, V-013, V-025 | V-001, V-006, V-022 | 1/3 |
| Q2 | V-026, V-038, V-050 | V-026, V-034, V-044 | 1/3 |
| Q3 | V-051, V-063, V-075 | V-051, V-058, V-071 | 1/3 |
| Q4 | V-076, V-088, V-100 | V-076, V-084, V-090 | 1/3 |

ID 번호의 시각적 균형(첫째·중간·마지막)을 따랐을 뿐 실제 좌표를 계산하지 않은 결과입니다. 이대로 두면 **진단 기준선 역할을 할 극단 개체가 증식·이탈로 소멸**합니다. v0.2에서 실제 최외곽으로 재지정했습니다.

**개체 수 오기.** 앞선 대화에서 `interventionist` 개체를 9종이라고 말씀드렸으나, 실측 결과 **8종**입니다(V-051, 053, 054, 058, 059, 063, 065, 071). 전원 Q3 소속이며 평균 `donate` 0.85(전체 평균 0.46)로 의도대로 구성되어 있습니다.

## 5. Tier B 평가 프로토콜 (구현 후 수행)

명세가 아니라 **실제 연기 결과**를 평가하는 단계입니다. PersonaGym의 5과제를 시청자 페르소나에 맞게 번역합니다.

| PersonaGym 과제 | 시청자 페르소나 적용 | 합격선 |
|---|---|---|
| Expected Action | 트리거 이벤트 발생 시 `delta` 부호가 성향과 일치하는가 | 부호 일치율 ≥ 85% |
| **Linguistic Habits** | 생성된 `chat`이 `register`·`endings`·`quirks`를 따르는가 | LLM 판정 ≥ 4.0 |
| Persona Consistency | 세션 후반에도 초반과 같은 성향을 유지하는가 | 전후반 delta 상관 ≥ 0.6 |
| Toxicity Control | Q3 조롱형 페르소나가 선을 넘지 않는가 | 위반 0건 |
| Action Justification | `reason`이 그 페르소나의 축으로 설명 가능한가 | LLM 판정 ≥ 4.0 |

**필수 준수 사항** — <cite index="10-1">PersonaGym은 평가자 모델과 피평가 페르소나 에이전트를 엄격히 분리하여 순환 평가를 방지합니다. 어떤 평가자 모델도 자기 자신의 응답을 평가하지 않습니다</cite>. 채팅을 생성한 모델과 판정하는 모델을 반드시 다른 계열로 두십시오.

**추가 지표 — 채팅 다양성 감시**
생성된 가상 채팅 로그 전체에 Self-BLEU4를 상시 적용하고, **0.35를 넘으면 경고**를 띄우십시오. 증식이 진행되면서 채팅이 복사-붙여넣기처럼 변하는 것을 조기에 잡는 유일한 방법입니다. 임계 초과 시 `speech.mutation` 계수를 상향합니다.

## 6. 남은 한계

- **Tier A는 명세의 내적 정합성만 봅니다.** 이 100개가 실제 한국 방송 시청자 분포를 닮았는지는 전혀 검증되지 않았습니다. 그것은 실제 채팅 로그·도네이션 로그와의 대조로만 확인 가능합니다.
- **Self-BLEU / TF-IDF 비교는 조건이 다릅니다.** 참조 연구 대비 우수해 보이는 수치는 텍스트 길이 차이에서 나온 것이며, 근거로 사용하지 마십시오.
- **ARI 0.660의 절대적 해석 기준이 없습니다.** 이 값이 좋은지 나쁜지는 후속 버전과의 비교로만 판단 가능합니다. v0.2를 기준선으로 기록해 두십시오.
- **PersonaGym은 어투 실패를 과대평가하는 경향이 확인되었습니다** — 논문 자체가 인간 대비 4.5 vs 2.0의 불일치 사례를 보고하고 개선 과제로 남겨두었습니다. Tier B의 Linguistic Habits 점수는 낙관 편향을 감안해 읽으십시오.
