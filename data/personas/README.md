## 1. 두 개의 층 — 발화층과 판정/평가층

페르소나가 하는 일은 성격이 다른 둘로 갈린다. 섞으면 C3(관측·발화만)가 깨진다.

| | **발화층** (기존, 가동 중) | **판정/평가층** (신규, PAE) |
|---|---|---|
| 하는 일 | 게임 이벤트를 관측해 **채팅을 생성** | 게임의 **흥미도 곡선을 진단** |
| 산출물 | 화면에 뜨는 시청자 발화 1줄 | 페르소나별 Δ 시계열·병목 좌표·리포트 |
| 대표 자산 | 8종 톤 페르소나(`games/shell/chat.js`), 게임별 어휘(`games/*/chat-data.js`) | `PAE_설계명세서.md`, 100종 JSON |
| C3 위치 | **C3 준수** — 룰 수치에 관여 안 함, 말만 한다 | **인게임 아님** — 설계/QA 도구다 (아래 경고) |

> **⚠ C3 경계 (절대):** PAE의 **Player Fork는 게임을 직접 플레이(의사결정)한다.** 이것은
> 인게임 AI 시청자가 아니라 **디자이너를 위한 흥미도 평가 도구**다. 런타임 채팅(발화층)은
> 여전히 관측·발화만 하며 룰 수치에 관여하지 않는다(C3a). PAE가 산출한 곡선·진단은
> 디자이너가 읽는 리포트일 뿐, 경제·룰의 런타임 입력이 될 수 없다(C3b 단방향 불변식,
> `docs/resonance-model.md` 주요④와 동일 원칙). 두 층은 코드·데이터가 분리 유지된다.

## 2. 세 가지 페르소나 모델의 관계 (미해결 — 통합 매핑 필요)

현재 프로젝트에는 축 체계가 다른 페르소나 모델이 **셋** 존재한다. 통합 매핑은 후속 과제다.

| 모델 | 축 | 규모 | 쓰임 | 출처 |
|---|---|---|---|---|
| **톤/3축 덮개** | 위험 선호·정보 깊이·애정 온도 (+ 톤 6종) | 8종 | 발화층(가동 중) | `prototypes/05-hwaryeok-personas.md` |
| **PAE Genome 6축** | CHL·OPT·RSK·NOV·PAT·SOC | 8~16 (탐색/검증) | 판정/평가층 | `PAE_설계명세서.md` §2 |
| **100종 2축** | x=자극원(숙련↔혼돈)·y=몰입대상(판↔사람) | 100종 | 발화층 확장 + Spectator 개체군 | `viewer_personas_100_v02.json` |

- **100종 2축**은 발화층의 8종을 대체·확장할 후보이자, 동시에 PAE **Spectator Fork의
  개체군**이 될 수 있다. `speech` 구조가 발화층을(톤 필터 탈피 — 05-personas §4.5 우선순위 #1),
  `triggers/repellents/delta 부호`가 판정층을 각각 먹인다.
- **6축 Genome ↔ 2축**: PAE는 Seed 1개에서 자가복제(`replicate()`)하는 소수 정예(8~16)를
  전제하고, 100종은 이미 펼쳐진 개체군이다. 100종의 x/y와 6축(특히 RSK·NOV·SOC)의 사상표가
  아직 없다 — **v0.3에서 확정할 것.**
- **참조되나 부재한 문서:** 평가 리포트가 §5.3(자식 생성)·§2.2(Y축 주장)·§7(불멸 관측자)로
  인용하는 것은 100종 JSON 자체의 **2축 설계 문서**이며, PAE 명세서와 별개다. 이 2축 설계
  문서는 아직 레포에 없다 — 확보/작성이 필요하다.

## 3. 평가 플로우 (Tier A → Tier B)

페르소나 품질은 두 단계로 검증한다. **명세를 만든 뒤(Tier A), 연기시킨 뒤(Tier B).**

- **Tier A — 정적 명세 평가 (실측 완료, `평가리포트` §3):** 축 직교성(x–y Spearman 0.08 ✅),
  4사분면 균형, 커버리지(태그 36/36), 식별가능성(행동만 ARI 0.660), 텍스트 다양성.
  실행/기준 프레임워크: PersonaGym·Self-BLEU4·ARI·Centroid.
- **Tier B — 런타임 연기 평가 (구현 후, `평가리포트` §5):** PersonaGym 5과제를 시청자용으로
  번역 — Expected Action(Δ 부호 일치 ≥85%)·Linguistic Habits(≥4.0)·Persona Consistency
  (전후반 Δ상관 ≥0.6)·Toxicity Control(위반 0)·Action Justification(≥4.0).
  **필수: 채팅 생성 모델 ≠ 판정 모델**(순환 평가 금지). 생성 채팅에 Self-BLEU4 상시 감시,
  **0.35 초과 시 경고 → `speech.mutation` 상향.**
- **PAE 자체 검증 게이트 (`PAE_설계명세서.md` §9):** 인간 RankTrace 곡선과 Spearman r.
  r≥0.60 합격 / 0.40–0.60 조건부 / <0.40 재설계. 편향보정 3종(반복-중앙값·순서 스왑·이종
  모델 앙상블) 필수. 프롬프트는 커밋 해시와 함께 기록(한 줄 수정이 곡선 전체를 바꾼다).

## 4. 크로스도메인 후속 (타 영역 리뷰 필요 — 이 PR에서 손대지 않음)

이 셋은 공동/타 영역 소유라 무단 변경하지 않았다. PR·ADR-003에 리뷰 요청으로 남긴다.

1. **`docs/contract.md` §2 (공동 — 정훈·현재 상호 리뷰):** 현행 페르소나 형식은
   `{nick, color, tones}` + v2 예약(interest/valence/threshold). 100종의 `speech` 구조와
   행동 파라미터(arrival/patience/donate/spawn/volume)를 스키마로 승격할지 결정 필요.
2. **`docs/resonance-model.md` (소윤·정훈):** 평가 리포트 §3.3 실측이 설계 주장을 뒤집었다 —
   **"Y축이 신규 유입 지배"는 틀렸고, 신규 유입(spawn/증식)은 X축(혼돈)이 지배**(spawn~x=0.54
   > spawn~y=−0.32). 함의: **바이럴=혼돈 이벤트, 수익(도네)=사람 서사.** `spawn`은 공명 모델의
   **변이/버즈**와 직결되므로 정훈 반영 필요.
3. **직교성 기준 정정:** `replicate()`의 `d_min=0.35`는 N=8 가정값. 일반식 **`d_min=0.5/√N`**
   으로 대체(N=100→0.05). PAE 명세서 §3.1과 100종 설계 문서 양쪽에 반영 필요.
