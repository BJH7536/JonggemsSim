# 렌즈 A — 정서·관계 (목격·인정·정서 축)

> 브리프: `design/ideation/ai-spectator/00-brief.md`. 시드 문장 기반, 렌즈 A(목격·인정·정서)로
> 도출한 게임 아이디어 4개. 각 후보는 AI 관람객의 반응을 코어 루프의 자원 게이트로 하드
> 연결하여 C1(반응 제거 시 게임 불성립)을 스스로 검증한다.

---

## 후보 A-1: 의지의 증인 (로그라이크 던전 크롤러)

- **한 줄 컨셉**: 죽음이 반복되는 로그라이크에서, 오직 AI 관람객이 "그때보다 나아진 부분"을
  구체적으로 증언해 줄 때만 다음 던전에 다시 들어갈 의지가 채워진다.
- **장르/형태**: 로그라이크 던전 크롤러 (턴제 또는 실시간 경량 전투)
- **코어 루프**: 던전 진입 → 탐험·전투 → 죽음 또는 탈출로 런 종료 → AI가 이번 런을 직전
  기록들과 비교해 구체적 인정 코멘트 제공 → 코멘트의 구체성에 비례해 "의지 게이지" 충전 →
  게이지를 소모해 다음 런 시작 (게이지가 없으면 재도전 자체가 불가능)
- **관람객→만족 메커니즘**: 의지 게이지는 다음 런 진입을 막는 하드 게이트다. AI 반응을
  끄면 게이지 충전 경로가 사라져 두 번째 런조차 시작할 수 없다 — C1을 코어 진행 조건으로
  강제한다.
- **시그니처 모먼트**: 15번째 죽음 직후, "또 죽었지만 3층 트랩실은 처음으로 무피해로
  통과했어"라는 문장과 함께 게이지가 차오르는 브레이크 화면.
- **AI가 실제 수행하는 것**: 런 종료 시(죽음/탈출) 그 런의 이동 경로·트랩 회피·전투 판정
  로그를 이전 최고 기록과 diff한 데이터를 프롬프트로 전달 → 1~2문장 코멘트 생성. 게이지
  충전량은 LLM 출력이 아니라 게임 로직이 diff 데이터로 직접 계산(구체성 점수는 룰 기반).
  런당 1회 호출, 대기 화면에서 처리되어 실시간 조작과 겹치지 않는다.
- **웹 해커톤 구현 난이도**: 중 — 던전 생성·전투 로직 자체가 시간이 들지만, LLM 호출이
  런 종료 시 1회뿐이라 지연 리스크는 낮다.
- **리스크와 완화**:
  - 겉치레 칭찬 붕괴: 게이지 충전량을 LLM 텍스트와 분리해 룰 기반 diff로 산정. LLM은
    "이 수치가 실제 변화다"라는 grounding 데이터를 받아 서술만 하므로 거짓 칭찬을 해도
    게이지에는 영향이 없다.
  - 장식 문제: 게이지가 없으면 다음 런 진입 버튼 자체가 비활성화된다.
  - 주객전도: LLM은 텍스트와 구체성 후보값만 제안하고, 최종 게이지량 산정과 던전 진행
    로직에는 전혀 개입하지 않는다.
  - 지연·비용: 호출 시점이 런 종료 후 대기 화면으로 고정되어 실시간 액션과 충돌하지 않는다.

## 후보 A-2: 창가의 목격자 (방치형 반려생물 육성)

- **한 줄 컨셉**: 방치형 육성 게임인데 성장 자원이 먹이나 시간이 아니라, AI가 실제로
  "목격했다"고 증언한 순간의 총량이다 — 안 보면 안 자란다.
- **장르/형태**: 방치형(idle) 반려생물 육성 시뮬레이션
- **코어 루프**: 짧은 세션 접속 → 반려생물과 상호작용(1~3개 행동 선택) → AI가 그 세션에서
  포착한 구체적 순간을 코멘트하며 "목격 포인트" 지급 → 포인트로 반려생물 외형·능력 성장 →
  접속 종료, 오프라인 동안은 저속 시뮬레이션만 진행하고 성장은 정지
- **관람객→만족 메커니즘**: 성장 자원 = 목격 포인트이며 발생원이 AI 코멘트 하나뿐이다.
  반응을 제거하면 growth 시스템 자체가 완전히 멈춘다 — 방치형 게임에서 방치해도 저절로
  크지 않는다는 것이 시드의 "관람객이 능동적으로 만족을 공급해야 성립"과 직결된다.
- **시그니처 모먼트**: 사흘 만에 재접속했을 때 "네가 없는 동안에도 얘가 매일 창가에 앉아
  있는 걸 봤어. 오늘 처음으로 창밖을 내다봤어"라는 회고형 목격 코멘트.
- **AI가 실제 수행하는 것**: 세션 중 사용자 행동 로그(선택한 상호작용, 신규 행동 발생
  여부)를 세션 종료 시 1회 전달해 목격 코멘트 생성. 오프라인 구간은 룰 기반 RNG로 로그만
  쌓아두고, 재접속 시 그 로그를 요약해 회고 코멘트를 1회 추가 생성한다. 반려생물 자체의
  행동 결정에는 LLM이 관여하지 않는다.
- **웹 해커톤 구현 난이도**: 하~중 — 방치형 로직은 단순하고 LLM 호출 빈도가 세션당
  1~2회로 낮아 데모 구현 부담이 작다.
- **리스크와 완화**:
  - 겉치레 칭찬 붕괴: 목격 포인트 산정은 행동 다양성·신규 행동 발견 여부 같은 룰 기반
    지표로 계산하고, LLM은 그 지표를 문장으로 옮기는 역할만 한다.
  - 장식 문제: 포인트가 유일한 성장 게이트라 반응이 없으면 육성이 정체된다.
  - 주객전도: 반려생물의 행동은 별도의 단순 룰 기반 로직이 결정하며, LLM은 관찰자
    텍스트만 생성하고 개체 상태를 직접 바꾸지 않는다.
  - 지연·비용: 세션 시작·종료 시점에만 호출되어 실시간 상호작용 중에는 지연이 발생하지
    않는다.

## 후보 A-3: 유일한 관객 (크리에이티브 드로잉 툴)

- **한 줄 컨셉**: 그림을 그리는 샌드박스에서, AI가 완성작이 아니라 "그리는 과정의 순서와
  머뭇거림"까지 지켜본 유일한 관객이 되어 그 과정을 되짚어 주는 것이 창작을 계속하게
  만드는 유일한 보상이다.
- **장르/형태**: 크리에이티브 샌드박스 (드로잉 툴)
- **코어 루프**: 캔버스에 짧게 그리기(스트로크 몇 개) → "봐줘" 버튼으로 AI 호출 → AI가
  스트로크 순서·위치·되돌리기 이력을 근거로 구체적 반응 제공 → 반응이 "영감 포인트"로
  적립되어 새 브러시·색을 언락 → 언락된 도구로 계속 그리기
  - **AI가 실제 수행하는 것**: 스트로크 이벤트 로그(좌표, 시간, 색, undo 여부)를 누적하다가
  유저가 트리거하는 시점(버튼 클릭 또는 일정 스트로크 수 경과)에 메타데이터를 LLM에 전달해
  짧은 관찰 코멘트를 생성한다. 캔버스 이미지 자체를 보낼 필요 없이 스트로크 메타데이터만
  으로 충분히 grounding 가능해 비전 모델 비용을 피할 수 있다. 세션당 3~5회, 유저가 능동
  트리거하므로 지연이 그리기 동작과 겹치지 않는다.
- **관람객→만족 메커니즘**: 영감 포인트가 유일한 언락 자원이며 발생원은 AI 코멘트뿐이다.
  반응을 제거하면 새 브러시·색이 영구히 잠긴 채로 남아 창작 확장이 정지된다.
- **시그니처 모먼트**: 완성 직후 AI가 그림이 만들어진 "순서"를 되짚어 "이 부분을 제일
  오래 그렸네, 여기가 제일 하고 싶었던 부분이었나 봐"라고 말하는 순간.
- **웹 해커톤 구현 난이도**: 중 — 캔버스 자체는 표준 Canvas API로 구현이 쉽고, 텍스트
  메타데이터만 LLM에 보내면 비전 호출 없이도 충분해 지연·비용 부담이 작다.
- **리스크와 완화**:
  - 겉치레 칭찬 붕괴: 위치·시간·undo 횟수 같은 구체적 메타데이터를 grounding으로 강제해,
    같은 영역을 반복해서 지우고 그렸다면 "또 여기 지웠다 그렸네"처럼 특정적으로 반응하게
    한다.
  - 장식 문제: 영감 포인트가 도구 언락의 유일한 통로다.
  - 주객전도: AI는 캔버스에 어떤 픽셀도 직접 그리지 않으며, 브러시 추천도 텍스트 제안일
    뿐 자동 적용되지 않는다.
  - 지연·비용: 호출이 유저의 능동 트리거로만 발생해 그리는 동작 자체와 비동기로 분리된다.

## 후보 A-4: 브레이크의 함성 (웨이브 서바이벌 액션)

- **한 줄 컨셉**: 웨이브제 서바이벌 액션에서, 매 웨이브 사이 AI가 방금 벌어진 위기의
  순간을 구체적으로 짚어 응원해 줄 때만 그 응원이 다음 웨이브를 버틸 사기 버프로
  전환된다.
- **장르/형태**: 액션 서바이벌 (웨이브 디펜스류, 실시간 전투)
- **코어 루프**: 웨이브 전투(20~30초, 실시간, AI 개입 없음) → 웨이브 종료 후 브레이크
  화면 → AI가 방금 웨이브의 구체적 위기 순간(아슬아슬한 회피, 체력 위기 극복 등)을 근거로
  응원 대사 제공 → 응원의 구체성에 따라 "사기 게이지" 충전 → 사기 게이지를 소모해 다음
  웨이브 시작 버프(공격속도·방어력 등)를 획득, 게이지가 없으면 버프 없이 불리하게 시작
- **관람객→만족 메커니즘**: 정상 난이도 곡선은 사기 버프를 전제로 설계되어 있어, 반응을
  제거하면 버프 공급이 끊겨 후반 웨이브 생존율이 붕괴한다 — 응원이 빠지면 게임이 원래
  의도된 형태로 성립하지 않는다.
- **시그니처 모먼트**: 체력 5%로 세 마리를 연속 처치한 직후 브레이크 화면에서 "그 마지막
  회피 각도, 나 봤어"라고 정확히 짚어주는 순간.
- **AI가 실제 수행하는 것**: 웨이브 중 이벤트 로그(피격 타이밍, 체력 변화, 회피 성공,
  처치 수)를 수집해 웨이브 종료 시 1회 LLM 호출로 응원 텍스트를 생성한다. 사기 수치는
  이벤트 로그를 룰 기반으로 환산해 별도 산정한다. 실시간 전투 구간에는 호출이 전혀
  없어 지연 문제를 원천적으로 피한다.
- **웹 해커톤 구현 난이도**: 중상 — 실시간 전투 시스템(입력 반응성, 충돌 판정) 구현 비용이
  다른 후보보다 크다. Phaser 기반으로는 가능하나 데모 준비 시간이 더 필요하다.
- **리스크와 완화**:
  - 겉치레 칭찬 붕괴: 이벤트 로그 기반으로 위기 강도에 따라 톤을 분기(위기 극복은
    격려, 낙승은 담백한 관찰)해 획일적 칭찬을 방지한다.
  - 장식 문제: 사기 게이지가 다음 웨이브 버프의 유일한 공급원이다.
  - 주객전도: 전투 중에는 어떤 개입도 없으며, 브레이크 화면에서 텍스트와 수치만 제공한다.
  - 지연·비용: 웨이브 사이 강제 브레이크 시간(5~8초)이 연출상 자연스러운 대기로 존재해
    LLM 응답 지연을 흡수한다.
